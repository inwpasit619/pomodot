**Parent:** [map](../map.md)

## Question

เขียนกฎที่ผู้ใช้ยืนยันในตั๋ว 01 ลง [spec](../../pomodoro-v1/spec.md) เป็นหัวข้อใหม่ต่อจาก M6 แล้วสร้างตั๋ว implement ใน `.scratch/pomodot-build/issues/` (ต่อจากเลข 28) — นี่คือปลายทางของ map

ต้องมีใน spec:

- กฎหุบเข้าขอบ/มุม/กลางแบบ C จาก[ผลตั๋ว 01](01-prototype-where-the-card-shrinks-to.md#resolution) (ใกล้ขอบไม่ถึง 78 pt แนวนอน / 81 pt แนวตั้ง ระยะเดียวกับตอนขยาย ไม่ต้องชน) และขีดฆ่าข้อ M2 ที่ขัดกัน ("เลือกทิศตอนเริ่มขยาย แล้วไม่เปลี่ยนจนกว่าจะหุบ") พร้อมเหตุผลเดิมที่ยังต้องรักษา: การ์ดห้ามกระโดดหนีเมาส์
- เรื่องเทคนิคที่ agent ตัดสินแล้วอธิบายเป็นภาษาคน: เลือกทิศใหม่**ตอนปล่อยเมาส์หลังลาก** (การ์ดไม่ขยับ เปลี่ยนแค่ว่าแคปซูลอยู่ตรงไหนในการ์ด และตำแหน่งที่จำไว้ใน `state.json` ถูกตั้งแต่ตอนนั้น) หรือ**ตอนหุบ** (ครอบคลุมการ์ดที่ถูกย้ายโดยไม่ได้ลากด้วย เช่นถอดจอเสริม, Dock ขยาย, เปลี่ยนความละเอียด) — ย้ายมาจากหมอกใน map; prototype ใช้แบบตอนปล่อยเมาส์
- **ระยะต้อง dynamic** (ผู้ใช้ขอ): ห้ามเขียน 78 / 81 ลงโค้ด ให้ได้มาจาก `FloatingWindowPlacement.cardSize` กับ `capsuleSize` ที่กฎขยายใช้อยู่แล้ว — ทางที่แนะนำคือให้กฎหุบ**ถามกฎขยายเอง** ("ถ้าแคปซูลไปชิดขอบนี้ของการ์ด คลิกแล้วจะขยายออกจากขอบนี้ไหม") จะได้มีสูตรเดียว เปลี่ยนขนาดการ์ดแล้วทั้งขยายและหุบตามกันเอง; spec เขียนกฎเป็นสูตร (ขนาดการ์ด − ขนาดแคปซูล) ÷ 2 แล้วค่อยยกตัวอย่างตัวเลขของขนาดปัจจุบัน
- test ต้องมีค่าที่ขอบพอดี: ห่างน้อยกว่าระยะ 1 pt → หุบเข้าขอบ, ห่างเท่าระยะ → กลาง ทั้งสองแนว โดยคำนวณค่าที่คาดหวังจากขนาดการ์ด/แคปซูล ไม่ใช่ตัวเลขตายตัว; และ test "ขยาย → ลาก → หุบ → ขยาย ได้การ์ดที่เดิม" ทั่วหลายตำแหน่ง เป็นตัวกันพังถ้าขนาดเปลี่ยน
- animation ตอนหุบหดเข้าทิศใหม่ (ไม่ใช่ทิศตอนขยาย)
- test ของ Core seam 4 แบบ Given/When/Then ด้วยตัวเลขจริง (จอ (0, 0)–(1440, 875), แคปซูล 128×38, การ์ด 284×200) ครบกรณีในตั๋ว 01 รวมถึงขยาย→หุบ→ขยายแล้วการ์ดอยู่ที่เดิม
- checklist ทดสอบด้วยมือ (ลากจริงด้วยเมาส์ ทั้งสี่มุม ขอบเดียว และสองจอถ้ามี)
- เลขเวอร์ชัน: agent เสนอ (0.10.1 หรือ 0.11.0 ตามกติกา version ใน spec) แล้วให้ผู้ใช้อนุมัติ และหัวข้อ release notes

## Resolution

เสร็จ 2026-10-17 — **ถึงปลายทางของ map แล้ว**

- [spec](../../pomodoro-v1/spec.md) มีหัวข้อ **M7. การ์ดหุบเข้าขอบ/มุมที่อยู่ใกล้** (ขอบเขต, กฎหุบเข้าขอบ, เรื่องเทคนิค, Test (Core) M7, Checklist ทดสอบด้วยมือ M7, แจกจ่าย 0.11.0) และขีดฆ่าข้อ M2 ที่ขัดกันสองที่ ("เลือกทิศ…ไม่เปลี่ยนจนกว่าจะหุบ" ทั้งในกฎและใน test seam 4) แล้วเขียน "M7 ทับ"; สารบัญ, หัว "อ่านก่อนเริ่ม" และรายการฟีเจอร์ v1 มี M7
- **เวอร์ชัน `0.11.0`** — ผู้ใช้อนุมัติ (MINOR = เพิ่มฟีเจอร์)
- **เรื่องเทคนิคที่ agent ตัดสิน:** เลือกทิศใหม่**ตอนปล่อยเมาส์หลังลากการ์ด** ไม่ใช่ตอนหุบ — ตรงกับ prototype, ตำแหน่งใน `state.json` ถูกทันที, แก้ที่เดียวใน `released`; การ์ดที่ระบบย้ายยังหุบตามทิศเดิม (นอกขอบเขต); กฎหุบถาม `CardLayout(capsule:visibleFrame:)` เอง ไม่มีตัวเลขตายตัว
- ตั๋ว implement ใน `.scratch/pomodot-build/issues/`: [29 — การ์ดหุบเข้าขอบ/มุมที่อยู่ใกล้](../../pomodot-build/issues/29-m7-tuck-into-edge.md) และ [30 — ด่านปิด milestone + ออก 0.11.0](../../pomodot-build/issues/30-m7-gate-release.md)
- ต่อด้วย `/implement ticket 29`
