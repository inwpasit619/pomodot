# Map — การ์ดหุบเข้าขอบ/มุมที่มันชิดอยู่

**Label:** `wayfinder:map`

## Destination

หัวข้อใหม่ใน [spec](../pomodoro-v1/spec.md) (เขียนแบบ M1–M6: ขอบเขต พฤติกรรม test ของ Core seam 4 และ checklist ทดสอบด้วยมือ) พร้อมตั๋วใน `.scratch/pomodot-build/issues/` ให้ `/implement` ทำบน `feature/…` จนออกเวอร์ชันถัดไป: **ลากการ์ดไปชิดขอบหรือมุมจอแล้วหุบ → แคปซูลหุบเข้าขอบ/มุมนั้น ไม่ได้ชิดขอบ → หุบเข้ากลางการ์ด** (กลับด้านของการขยายใกล้ขอบที่มีอยู่แล้ว)

## Notes

- คุยกับผู้ใช้เป็นภาษาไทย ผู้ใช้ไม่เขียน Swift: agent ตัดสินใจเรื่องเทคนิคแล้วอธิบายข้อดีข้อเสียเป็นภาษาคน
- ใช้ `/grilling` + `/domain-modeling` (ศัพท์ใน `CONTEXT.md`: Floating Window, capsule, card …) และ `/prototype` สำหรับพฤติกรรม/หน้าตา
- กติกากลาง A1–A10 ของ spec ยังใช้ทั้งหมด (Core ไม่ import UI, checklist ทดสอบด้วยมือแบบ Given/When/Then, gitflow)
- ข้อเท็จจริงตอนเริ่ม (0.10.0):
  - การขยายใกล้ขอบอยู่ใน spec M2 หัวข้อ "การขยายใกล้ขอบจอ": การ์ดอยู่กลางแคปซูล ถ้าจะทะลุขอบไหนก็ชิดขอบแคปซูลด้านนั้นแทน (`CardLayout` ใน `Sources/Core/FloatingWindowPlacement.swift`)
  - spec M2 บอกว่า "เลือกทิศตอนเริ่มขยาย แล้วไม่เปลี่ยนจนกว่าจะหุบ" — ลากการ์ดไปไหน แคปซูลก็ติดไปที่จุดเดิมในการ์ด เลยหุบไม่เข้ามุม (ภาพที่ผู้ใช้ส่งมา: ลากการ์ดไปมุมขวาล่าง หุบแล้วแคปซูลลอยอยู่กลางที่การ์ดเคยอยู่)
  - ทิศของ animation ตอนหุบมาจาก `cardLayout` ที่เก็บไว้หลังหุบ (`FloatingView.swift`)
- **ตัดสินตอน charting (2026-10-17):** ใช้หลักเดียวกับตอนขยาย กลับด้าน — การ์ดชนขอบจอด้านไหน แคปซูลหุบเข้าขอบด้านนั้น ชนสองด้าน (มุม) ก็หุบเข้ามุม ไม่ชนขอบไหน หุบเข้ากลาง; "ชนขอบ" คือชนจริง (การ์ดลากทะลุขอบไม่ได้อยู่แล้ว ดันจนสุดก็ชน) ผลคือคลิกขยายอีกครั้ง การ์ดกลับมาที่เดิมเป๊ะ
