## Question

spec ต้องบอก agent ว่าแอพเก็บข้อมูล 3 ก้อนนี้ไว้ที่ไหนและในรูปแบบอะไร (agent เสนอทางที่แนะนำ + trade-off เป็นภาษาคน แล้วให้ผู้ใช้อนุมัติ ไม่ต้องลงรายละเอียด API)

1. **History** — Pomodoro ทุกอัน (เวลาจบแบบสากล + ความยาว) เก็บตลอดไป ลบได้ทั้งหมดผ่าน `Clear History…` (ตั๋ว "สถิติ/ประวัติ นับอะไร แสดงยังไง")
2. **สถานะ timer** — Phase, ตัวนับ Cycle, เวลาที่เหลือ, Phase ปัจจุบันเคยกด Start แล้วหรือยัง เปิดแอพใหม่ต้องกลับมาที่เดิมเป็น Pause (ตั๋ว "กติกาของ timer") และจำว่า Floating Window ซ่อนอยู่หรือไม่ (ตั๋ว "menu bar กับหน้าต่างลอย เกี่ยวกันยังไง")
3. **Settings** — เวลาแต่ละ Phase, Pomodoro ต่อ Cycle, auto-start 2 สวิตช์, Always on Top, ตัวเลือก notification และเสียง (รวมถึงตำแหน่งของ Floating Window ถ้าตั๋ว "หน้าตาและตำแหน่งของหน้าต่างลอย" ตัดสินว่าต้องจำ)

ต้องตัดสิน:
- แต่ละก้อนใช้วิธีไหน (เช่น UserDefaults, ไฟล์ JSON ใน Application Support, SwiftData/SQLite) ข้อสำคัญคือ ไม่ต้องลง library เพิ่ม, build ด้วย CLT + SwiftPM ได้ และ `swift test` ทดสอบได้โดยไม่ต้องเปิดแอพ
- ถ้าแอพ crash หรือไฟสะดุดตอนกำลังเขียน ข้อมูลต้องไม่พัง และถ้าไฟล์เสียแอพต้องเปิดได้ (เริ่มใหม่แทนการค้าง)
- เขียนสถานะ timer บ่อยแค่ไหน (ทุกครั้งที่สถานะเปลี่ยน หรือตอนจะปิดแอพ) เพื่อให้ quit หรือเครื่องดับแล้วกลับมาใกล้เคียงที่สุด
- เวอร์ชันใหม่ของแอพต้องอ่านข้อมูลของเวอร์ชันเก่าได้ (ต้องมีเลข version ในไฟล์ไหม)
- ข้อมูลจะเก็บไว้ที่ไหนบนเครื่องของเพื่อน และลบแอพทิ้งแล้วข้อมูลยังค้างอยู่ไหม (เขียนไว้ในขั้นตอนติดตั้ง/ถอนการติดตั้งของ README)

ข้อมูลที่มีแล้ว: CLT + SwiftPM, Swift 6.4, minimum macOS 14, แอพ ad-hoc sign ไม่มี sandbox แจกเป็น .zip

(ส่งต่อมาจากตั๋ว "หน้าตาและตำแหน่งของหน้าต่างลอย") Settings มีเพิ่มอีก 1 ค่า คือ **Appearance** (`System` / `Light` / `Dark` ค่าเริ่มต้นคือ System) และ**ต้องจำตำแหน่งของ Floating Window** ข้ามการเปิดแอพใหม่ ถ้าตำแหน่งที่จำไว้อยู่นอกจอทุกจอแล้ว ให้กลับไปตำแหน่งเริ่มต้น (กลางบนใต้ menu bar ของจอหลัก) ต้องตัดสินว่าตำแหน่งเก็บรวมกับ Settings หรือกับสถานะของหน้าต่าง (ถ้าผู้ใช้กด Restore Defaults ตำแหน่งควรรีเซ็ตด้วยไหม) และเก็บเป็นจุดไหนของแคปซูล (ตำแหน่งของแคปซูลตอนย่อ ไม่ใช่ตอนขยาย)

(ส่งต่อมาจากตั๋ว "spec จะสั่ง agent ให้จัดโครงสร้างโค้ดและทดสอบยังไง") โค้ดแบ่งเป็น **Core** (กติกาล้วน ห้าม import AppKit/SwiftUI) + **App** + **CoreTests** ใช้ `/tdd` และชื่อ test แบบ Given/When/Then ตั๋วนี้ต้องตัดสินด้วยว่าการแปลงข้อมูลเป็นไฟล์/อ่านกลับ (รวมถึงอ่านข้อมูลเวอร์ชันเก่า และไฟล์เสียแล้วเริ่มใหม่) อยู่ใน Core เพื่อให้ test ได้ไหม และเพิ่มเป็น seam ที่ 5 หรือเปล่า ส่วนที่ควรมี unit test: ไฟล์เสียหรืออ่านไม่ได้ → ได้ค่าเริ่มต้นแทนการค้าง, ข้อมูลเวอร์ชันเก่าอ่านได้, บันทึกแล้วโหลดกลับได้ค่าเดิม (สถานะ timer กลับมาเป็น Pause) checklist ทดสอบด้วยมือ: Quit กลางช่วงแล้วเปิดใหม่, Force Quit แล้วเปิดใหม่ (milestone 2 คือ "Timer เต็มระบบ" ต้องมีการจำสถานะ timer แล้ว)

## Answer

(ปิดเมื่อ 2026-10-15 คุยกับผู้ใช้ agent เป็นคนเสนอ ผู้ใช้อนุมัติทุกข้อ)

**1. วิธีเก็บ: ไฟล์ JSON 3 ไฟล์ในโฟลเดอร์เดียว**
```
~/Library/Application Support/<bundle-id>/
  ├── settings.json   ค่าทั้งหมดในหน้า Settings (รวมถึง Appearance)
  ├── state.json      สถานะ timer + Floating Window ซ่อนอยู่หรือไม่ + ตำแหน่งของมัน
  └── history.json    Pomodoro ทุกอัน (เวลาจบแบบสากล ISO 8601 UTC + ความยาวเป็นวินาที)
```
- `<bundle-id>` รอตั๋ว "ชื่อแอพ, bundle identifier และไอคอน" ตัดสิน
- ใช้ `Codable` + `JSONEncoder`/`JSONDecoder` ของ Foundation **ไม่ใช้ UserDefaults, SwiftData, SQLite และไม่ลง library เพิ่ม**
- เหตุผล: build ด้วย CLT ได้แน่นอน, `swift test` ทดสอบได้โดยไม่ต้องเปิดแอพ, ข้อมูลอยู่ที่เดียวทำให้ลบ/backup ง่าย, เปิดอ่านด้วยตาได้ ส่วนขนาดไม่เป็นปัญหา (วันละ 12 Pomodoro 5 ปี ≈ 1 MB)
- ข้อเสียที่ยอมรับ: ต้องเขียนโค้ดอ่าน/เขียนไฟล์เองแทน UserDefaults ที่มีให้สำเร็จรูป และ macOS ยังเขียนค่าเล็กๆ ลง preference ของแอพเอง (เช่น ตำแหน่งไอคอนบน menu bar) ซึ่งไม่ต้องสนใจ
- ทางที่ไม่เลือก: Settings ใน UserDefaults (ข้อมูลแยก 2 ที่, macOS แคชค่าเก่าไว้ถ้าลบไฟล์ด้วยมือ, test เสี่ยงไปใช้ค่าจริงของเครื่อง), SwiftData/SQLite (เกินความจำเป็น และไม่แน่ใจว่า macro ของ SwiftData build ด้วย CLT ได้)

**2. Core กับ App แบ่งงานกันยังไง → seam ที่ 5 "ข้อมูลที่บันทึกไว้"**
- **Core:** กำหนดรูปแบบไฟล์, แปลงข้อมูล ↔ JSON, ไม่มีไฟล์ → ค่าเริ่มต้น, อ่านไม่ออก → ค่าเริ่มต้น + บอก App ให้ย้ายไฟล์ไว้ข้างๆ, แปลงข้อมูลเวอร์ชันเก่า, ตรวจค่าที่ผิดทีละค่า
- **App:** รู้ว่าโฟลเดอร์อยู่ที่ไหน, อ่าน/เขียนดิสก์, ย้ายไฟล์เสีย
- seam ที่ 5: ข้อความในไฟล์ (หรือ "ไม่มีไฟล์") → Settings / สถานะ timer / History หรือ "อ่านไม่ออก ใช้ค่าเริ่มต้น" และทำย้อนกลับได้ (เพิ่มจาก seam 4 จุดในตั๋ว "spec จะสั่ง agent ให้จัดโครงสร้างโค้ดและทดสอบยังไง")
- **สถานะ timer บันทึกเป็น "ภาพตอน Pause ณ เวลาที่บันทึก" เสมอ:** Phase, ตัวนับ Cycle, **จำนวน Pomodoro ต่อ Cycle ของ Cycle ปัจจุบัน** (เพราะถ้าเปลี่ยนใน Settings จะเริ่มใช้ตอน Cycle ถัดไป ถ้าไม่จำ "2/4" จะกลายเป็น "2/6" ได้), เวลาที่เหลือ (วินาที), Phase ปัจจุบันเคยกด Start แล้วหรือยัง โหลดกลับมาแล้วเป็น Pause ได้เอง และช่วงที่ปิดแอพไว้ไม่นับเวลา ตรงกับตั๋ว "กติกาของ timer"

**3. ความปลอดภัยของข้อมูล**
- เขียนทุกไฟล์แบบ **atomic** (เขียนลงไฟล์ชั่วคราวก่อนแล้วสลับมาแทน เช่น `Data.write(to:options: .atomic)`) ถ้า crash หรือไฟดับตอนเขียน ไฟล์เดิมจะยังอยู่ครบ
- **ไฟล์อ่านไม่ออก** (JSON เสีย หรือ version สูงกว่าที่รู้จัก) → เปลี่ยนชื่อเป็น `<ชื่อ>.corrupt-<yyyy-MM-dd'T'HH-mm-ss>.json` เก็บไว้ในโฟลเดอร์เดิม แล้วใช้ค่าเริ่มต้น **ห้ามเขียนทับไฟล์เสีย** ใช้กติกาเดียวกันกับทั้ง 3 ไฟล์ **ไม่แสดงกล่องแจ้งเตือน** เขียนลง log ของระบบอย่างเดียว เหตุผล: History เก็บไว้ตลอดไป ถ้าเขียนทับข้อมูลจะหายถาวร การเก็บไฟล์เสียไว้ทำให้ยังกู้คืนได้
- **ไฟล์อ่านได้ แต่บางค่าหายหรือผิด** (เช่น ไม่มี Appearance, Focus = -5) → แก้**แค่ค่านั้น**ให้เป็นค่าเริ่มต้น ค่าอื่นเก็บไว้เหมือนเดิม ไม่ถือว่าทั้งไฟล์เสีย ส่วน History ถ้ามีรายการที่เสียให้ข้ามแค่รายการนั้น

**4. บันทึกบ่อยแค่ไหน**
- `state.json`: บันทึกทุกครั้งที่สถานะเปลี่ยน (ปุ่ม, จบ Phase, auto-pause ตอน sleep, เปลี่ยน Settings, ซ่อน/แสดง/ลาก Floating Window) **+ ทุก 30 วินาทีระหว่างที่ timer เดิน** + ตอน Quit ถ้า Force Quit / crash / ไฟดับ จะเสียเวลาไม่เกิน 30 วินาที เปิดใหม่เป็น Pause
- `history.json`: บันทึกทุกครั้งที่ได้ Pomodoro และตอน `Clear History…` (เขียนทั้งไฟล์ใหม่แบบ atomic)
- `settings.json`: บันทึกทุกครั้งที่เปลี่ยนค่า
- ลำดับตอนจบ Focus: **บันทึก History ก่อนสถานะ timer เสมอ** กรณีที่ยอมรับไว้ (เกิดยากมาก): ถ้าแอพดับในเสี้ยววินาทีระหว่าง 2 ขั้นนี้ เปิดใหม่อาจได้ Pomodoro ซ้ำ 1 อัน ได้เกินมาดีกว่าข้อมูลหาย ไม่ต้องทำอะไรเพิ่มเพื่อกันกรณีนี้

**5. เลข version**
- ทุกไฟล์มี `"version": 1` อยู่ด้านบน
- **เพิ่มค่าใหม่ไม่ต้องเพิ่มเลข** เวอร์ชันใหม่อ่านไฟล์เก่าแล้วใช้ค่าเริ่มต้นแทนค่าที่ไม่มี (กติกา "แก้ทีละค่า") ส่วนเวอร์ชันเก่าที่อ่านไฟล์ใหม่จะข้ามค่าที่ไม่รู้จัก
- **เพิ่มเลขเฉพาะตอนเปลี่ยนโครงสร้าง** (เปลี่ยนชื่อค่า, เปลี่ยนหน่วย) ต้องมีโค้ดแปลงจากเวอร์ชันก่อนหน้าใน Core และต้องมี test
- เก็บ**ไฟล์ตัวอย่าง version 1** ไว้ใน test (ใช้ตัวอย่างจาก spec) เพื่อจับกรณีที่ agent เผลอเปลี่ยนรูปแบบไฟล์
- downgrade ไม่รองรับ: แอพเก่าเจอ version ที่สูงกว่า → ใช้กติกาไฟล์อ่านไม่ออก (ย้ายไว้ข้างๆ แล้วเริ่มใหม่)

**6. ตำแหน่งของ Floating Window**
- เก็บใน `state.json` (ไม่ใช่ `settings.json`) รวมกับ "ซ่อนอยู่หรือไม่"
- **Restore Defaults ไม่รีเซ็ตตำแหน่ง** คืนค่าแค่สิ่งที่อยู่ในหน้า Settings
- เก็บ**จุดกึ่งกลางของแคปซูลตอนย่อ** ในพิกัดของจอรวมทุกจอ (ไม่เก็บตอนขยาย) ถ้าจุดนี้ไม่อยู่ในพื้นที่ใช้งานของจอไหนเลย → กลับไปตำแหน่งเริ่มต้นกลางบนใต้ menu bar ของจอหลัก

**7. ถอนการติดตั้ง / อัปเดต**
- แอพไม่มี sandbox ข้อมูลเลยแยกจากตัวแอพ: **ลบแอพ → ข้อมูลยังอยู่** ลงใหม่ก็กลับมาครบ, **อัปเดตด้วยการเอาแอพใหม่ไปทับ → ข้อมูลยังอยู่** ตราบใดที่ bundle identifier ไม่เปลี่ยน
- README มีหัวข้อ **"ถอนการติดตั้ง"** ทำผ่าน Finder ได้ ไม่ใช้ Terminal: (1) Quit แล้วลากแอพลงถังขยะ (2) ถ้าอยากลบข้อมูลด้วย: Finder › Go › Go to Folder… → `~/Library/Application Support/<bundle-id>` → ลบโฟลเดอร์ (3) ไม่บังคับ: ลบรายการของแอพใน System Settings › Notifications และมีบรรทัดบอกว่า "ลบแอพอย่างเดียว History ยังอยู่"
- **ไม่มี**ปุ่ม "ลบข้อมูลทั้งหมด" หรือ "Show Data Folder" ในแอพ

**8. Test**
- Unit test ของ seam ที่ 5 (Given/When/Then):
  1. บันทึกแล้วโหลดกลับ ได้ค่าเดิมครบทั้ง 3 ไฟล์
  2. สถานะ timer ที่บันทึกตอนเดินอยู่ โหลดกลับมาเป็น Pause ด้วยเวลาที่เหลือ ณ ตอนบันทึก
  3. จำนวน Pomodoro ต่อ Cycle ของ Cycle ปัจจุบันยังเป็นค่าเดิม แม้ Settings จะเปลี่ยนไปแล้ว
  4. ไม่มีไฟล์ → ค่าเริ่มต้น (Focus 1/4 เต็มเวลา หยุดรอ, 25/5/15/4, History ว่าง)
  5. ไฟล์อ่านไม่ออก หรือ version สูงกว่าที่รู้จัก → ค่าเริ่มต้น + บอกให้ย้ายไฟล์ไว้ข้างๆ
  6. ขาดบางค่า / ค่าผิด → แก้แค่ค่านั้น ค่าอื่นยังเหมือนเดิม
  7. ไฟล์ตัวอย่าง version 1 อ่านได้ถูกต้องเสมอ
  8. History หลายพันรายการบันทึกแล้วโหลดกลับได้ครบ เวลาจบตรงเป๊ะ
- Checklist ทดสอบด้วยมือ (`docs/manual-test.md`):
  - (milestone 2) Quit กลาง Focus แล้วเปิดใหม่ → ทุกอย่างเหมือนเดิม เป็น Pause
  - (milestone 2) Force Quit กลาง Focus แล้วเปิดใหม่ → เวลาคลาดไม่เกิน 30 วินาที เป็น Pause
  - (milestone 2) ซ่อน Floating Window / ลากไปไว้มุมจอ แล้ว Quit และเปิดใหม่ → ยังซ่อนอยู่ / อยู่ที่เดิม
  - (milestone 5) Restore Defaults → ค่าใน Settings กลับเป็นค่าเริ่มต้น แคปซูลไม่ย้าย
  - (milestone 4) ทำ Pomodoro ให้ครบ แล้ว Quit และเปิดใหม่ → Statistics ยังนับครบ
  - (milestone 5) ลบแอพแล้วลงใหม่ → History ยังอยู่ / ลบโฟลเดอร์ข้อมูลตาม README → เริ่มใหม่สะอาด
  - ข้อ "ไฟล์เสีย" ไม่อยู่ใน checklist (unit test ข้อ 5 ครอบคลุมแล้ว)
