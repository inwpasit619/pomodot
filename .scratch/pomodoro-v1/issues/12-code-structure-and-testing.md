## Answer

(ปิดเมื่อ 2026-10-15 คุยกับผู้ใช้ agent เป็นคนเสนอ ผู้ใช้อนุมัติทุกข้อ)

**1. แบ่ง Swift package เป็น 3 target**
- **Core** (library) มีกติกาทั้งหมด ได้แก่ timer, ตัวนับ Cycle, Skip/Reset/New Cycle, auto-start, Expected finish, กติกาถามยืนยัน, เลือกข้อความ banner, แบ่ง History เป็นวัน/สัปดาห์, ตำแหน่งและท่าทางของ Floating Window **ห้าม import AppKit / SwiftUI / UserNotifications** (Foundation ใช้ได้)
- **App** (executable) มี menu bar, Floating Window, Settings, Statistics, เสียง และ notification ทำหน้าที่แค่ส่งเหตุการณ์ (ปุ่มที่กด, เครื่อง sleep, หมดเวลา) ไปให้ Core แล้ววาดผลที่ได้กลับมา ไม่มีกติกาของตัวเอง
- **CoreTests** ทดสอบแค่ Core
- เหตุผล: `swift test` ตรวจกติกาได้ครบในไม่กี่วินาทีโดยไม่ต้องเปิดแอพ และทุกหน้าจอใช้สมองตัวเดียวกัน ข้อเสียที่ยอมรับ: ต้องมีโค้ดส่งต่อระหว่าง target และส่วนที่เป็น UI ต้องใช้ checklist ทดสอบด้วยมือ

**2. เวลา: Core ไม่ดูนาฬิกาเอง**
- Core ห้ามเรียกเวลาปัจจุบันเองและห้ามมี timer ในตัว ทุกคำสั่งหรือคำถามที่ขึ้นกับเวลาต้องรับ `now` จากผู้เรียก
- ตอนเดิน Core จำแค่ "เริ่มเดินตอนไหน + ตอนนั้นเหลือกี่วินาที" เวลาที่เหลือ = ค่าที่จำไว้ − (now − ตอนเริ่ม) ห้ามนับลดทีละวินาที
- App มี timer ประมาณ 1 วินาทีไว้ถาม Core เพื่อวาดตัวเลขใหม่และเช็กว่า Phase หมดหรือยัง เครื่องจะ sleep → App ส่ง "pause ณ now" ให้ Core เปิดแอพใหม่ → Core โหลดเวลาที่เหลือแล้วอยู่ในสถานะ Pause
- เหตุผล: test ส่งเวลาปลอมเข้าไปได้ทันที (ไม่ต้องรอ 25 นาที, ข้ามเที่ยงคืนได้) และเวลาไม่คลาดสะสม ไม่ใช้ทาง "fake clock" แบบฉีดเข้าไป เพราะ test ซับซ้อนกว่าและเสี่ยงคลาดสะสม

**3. Unit test**
- agent ที่มา build ต้องใช้ skill **`/tdd`** กับ Core (red → green ทีละ test, vertical slice, test ผ่าน interface สาธารณะเท่านั้น)
- **seam กำหนดไว้ใน spec เลย** agent ไม่ต้องไปถามผู้ใช้ซ้ำ มี 4 seam:
  1. **Timer** — เหตุการณ์ (▶︎/⏸, Skip, Reset, New Cycle, sleep, หมดเวลา, เปิดแอพใหม่, เปลี่ยน Settings) → Phase, ตัวนับ, เวลาที่เหลือ, Expected finish, Pomodoro ที่เกิดขึ้น, ต้องถามยืนยันไหม
  2. **History / Statistics** — รายการ Pomodoro + now + ปฏิทินเครื่อง → Today / Week / All Time / กราฟ 7 วัน
  3. **ข้อความแจ้งเตือน** — เหตุการณ์จบ Phase + สวิตช์ auto-start → แจ้งเตือนไหม และใช้ข้อความอะไร
  4. **ตำแหน่งและท่าทางของ Floating Window** — ตำแหน่งแคปซูล + ขนาดจอ → ทิศที่การ์ดขยาย, ตำแหน่งที่จำไว้แต่อยู่นอกจอ → ตำแหน่งเริ่มต้น, กติกาชี้ค้าง/คลิก/ลาก (ถ้าแยกเป็น logic ล้วนได้)
- ใช้ **Swift Testing** ชื่อ test (display name) เป็นประโยค **Given / When / Then** ภาษาอังกฤษ ใช้คำจาก `CONTEXT.md` ในตัว test มีคอมเมนต์ `// Given` `// When` `// Then` แบ่งส่วน ตัวอย่าง: `@Test("Given a Focus at 2/4, when it is skipped, then it moves to Short Break and the count stays 2/4")` **ไม่ใช้ Cucumber / ไฟล์ `.feature`** (library ของ Swift ต้องพึ่ง XCTest ซึ่ง CLT ไม่มี และต้องลง dependency เพิ่ม)
- ค่าที่คาดหวังต้องมาจากตัวอย่างใน spec ห้ามคำนวณซ้ำแบบเดียวกับโค้ด (เป็น anti-pattern ตาม `/tdd`)
- **รายการพฤติกรรมที่ต้องมี test** (รวมมาจากตั๋วก่อนหน้า):
  - Timer: ลำดับปกติ Focus → Short/Long Break, Skip 3 กรณี (Focus ตัวนับไม่ขยับ / Short Break / Long Break → Cycle ใหม่), Reset ไม่แตะตัวนับ, New Cycle, Pause/Resume ต่อจากจุดเดิม, Focus ที่ pause แล้วทำต่อจนครบยังเป็น Pomodoro, auto-start 2 สวิตช์และหยุดเสมอหลัง Long Break, sleep → auto-pause (ล็อกจอแล้วไม่หยุด เป็นหน้าที่ของ App ที่ต้องไม่ส่งเหตุการณ์มา), เปิดแอพใหม่เป็น Pause, เปลี่ยนเวลาแล้วใช้กับ Phase ถัดไป / จำนวน Pomodoro ต่อ Cycle ใช้กับ Cycle ถัดไป / Phase ที่ยังไม่เคย Start ใช้ค่าใหม่ทันที, Expected finish ของ Phase กับ Cycle (นิ่งตอนเดิน, เลื่อนตอน Pause, skip Focus ทำให้ของ Cycle เลื่อน), ถามยืนยันเฉพาะตอนมีของจะหาย
  - ข้อความแจ้งเตือน: ข้อความถูกต้องตามกรณี (4 เหตุการณ์ × เริ่มเอง/รอกด) และไม่แจ้งเตือนตอน Skip / Reset / New Cycle / auto-pause
  - History / Statistics: แบ่งวันตามเวลาจบ (ข้ามเที่ยงคืน), วันแรกของสัปดาห์ตามการตั้งค่าเครื่อง, รวมเวลา Focus จากความยาวของแต่ละอัน, Focus ที่ skip/reset ไม่ถูกบันทึก, New Cycle ไม่ลบ History, Clear History ไม่กระทบ timer, กราฟ 7 วันมีช่องของวันที่ว่าง
  - Floating Window: ครึ่งบน → ขยายลง, ครึ่งล่าง → ขยายขึ้น, ชิดขอบซ้าย/ขวา → ชิดขอบนั้น, ตำแหน่งนอกจอ → ตำแหน่งเริ่มต้น, ชี้ค้าง 0.3 วิแล้วขยาย / ออก 0.5 วิแล้วหุบ / กดค้างแล้วลากไม่ขยาย / คลิกแล้วขยายทันที
  - การเก็บข้อมูล: ยังไม่กำหนด ส่งต่อให้ตั๋ว "เก็บข้อมูลของแอพไว้ที่ไหน รูปแบบอะไร"

**4. Checklist ทดสอบด้วยมือ**
- agent ทำไฟล์ `docs/manual-test.md` แบ่งหมวด: Floating Window / Menu bar / Notification & Sound / Statistics / Appearance / ติดตั้งบนเครื่องเพื่อน แต่ละข้อเป็น ☐ เขียนแบบ **Given / When / Then** ให้คนไม่เขียนโค้ดทำตามได้ ห้ามมีคำสั่ง terminal
- ใช้รายการทดสอบด้วยมือที่ส่งต่อมาจากตั๋ว "menu bar กับหน้าต่างลอย", "แจ้งเตือนกับเสียง", "สถิติ/ประวัติ" และ "หน้าตาและตำแหน่งของหน้าต่างลอย" (อยู่ในส่วน Question ด้านบน) บวกกับ: ขึ้นทับแอพ fullscreen, ไม่แย่ง focus, อยู่ทุก Space, menu bar อัปเดตสด, เปิดบนเครื่องเพื่อนผ่าน Open Anyway
- **agent ต้องทำเองก่อนในข้อที่ทำได้** (build, ประกอบ `.app`, เปิดแอพ, ถ่าย screenshot) แล้วส่งให้ผู้ใช้เฉพาะข้อที่ต้องใช้คน (ฟังเสียง, กด Allow, ลาก, เสียบ/ถอดจอ, เครื่องเพื่อน)

**5. Build เป็น 5 milestone** จบแต่ละช่วงต้องได้แอพที่เปิดใช้ได้ พร้อม checklist ของช่วงนั้น ผู้ใช้บอก "ผ่าน" ก่อนถึงไปช่วงถัดไปได้
1. **โครงแอพ + หน้าต่างลอย:** menu bar icon, ไม่มี Dock icon, แคปซูลลอยทับ fullscreen / ไม่แย่ง focus / อยู่ทุก Space, script build + ประกอบ `.app` + sign (ทำเรื่องที่เสี่ยงที่สุดก่อน)
2. **Timer เต็มระบบ:** ▶︎/⏸, Skip, Reset, New Cycle, การ์ดขยาย/หุบ/ลาก, Expected finish, เมนูควบคุมได้ครบ, Quit แล้วเปิดใหม่กลับมาที่เดิม
3. **แจ้งเตือน + เสียง**
4. **History + Statistics**
5. **Settings + Appearance + แจกจ่าย** (`.zip` + ลองบนเครื่องเพื่อน)
- ระหว่างช่วงที่ยังไม่มี Settings ให้ใช้ค่าเริ่มต้นไปก่อน

**6. เงื่อนไข "เสร็จ" ของทุก milestone** (ไม่ผ่านแม้แต่ข้อเดียว = ห้ามบอกว่าเสร็จ)
1. `swift test` ผ่านทุกข้อ
2. `swift build -c release --arch arm64 --arch x86_64` ผ่าน
3. ไม่มี warning ยกเว้น 2 ตัวที่รู้แล้ว (`ld: warning: search path ... not found` และ `x86_64 architecture is deprecated` ดูตั๋ว "ติดตั้ง CLT ใหม่แล้วตรวจว่า build ผ่าน") ถ้ามี warning ใหม่ต้องแก้ แก้ไม่ได้ต้องอธิบายเป็นภาษาคนในรายงาน
4. Core ไม่ import AppKit / SwiftUI / UserNotifications (ตรวจอัตโนมัติด้วย grep ใน script)
5. มี script คำสั่งเดียว build → ประกอบ `.app` → ad-hoc sign ทั้ง bundle แล้ว `codesign --verify` ผ่าน (หา path ด้วย `--show-bin-path`)
6. agent เปิดแอพจริงด้วย `open` แล้วแนบ screenshot
7. รายงานส่งงานเป็น**ภาษาไทย** มี 3 ส่วน: รายชื่อ test Given/When/Then ที่เพิ่มในช่วงนั้น / checklist ทดสอบด้วยมือที่เหลือให้ผู้ใช้ทำ / สิ่งที่ยังไม่ได้ทำหรือทำต่างจาก spec พร้อมเหตุผล
